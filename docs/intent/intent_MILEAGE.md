# Intent MILEAGE: пробег не больше 400 000 км, иначе — review

## Задача

Добавить в расчёт решения по заявке правило: пробег авто не больше 400 000 км;
при превышении порога решение понижается до `review`.

## Контекст (сверено с docs/setup/code_map.md и docs/plan/plan_MILEAGE.md)

- Сейчас решение выводится строго из LTV (`DecisionEngine::decide(float $ltv)`),
  пробег в решении не участвует.
- Пробег уже нормализуется в `ApplicationValidator` (int, 0…`max_mileage_km`
  = 500 000) и передаётся в `AssessmentService` — меняются только `DecisionEngine`,
  `AppFactory`, `rules.php` и тесты.
- 400 000 — порог решения; 500 000 — валидационный предел «вообще не принимаем».
  Разные величины с разной семантикой, валидацию не трогаем.

## Принятые решения

| Вопрос | Решение | Статус |
|---|---|---|
| Граница 400 000 | «Не больше» = `<=`: 400 000 → approve, 400 001 → review | по умолчанию, буквальная трактовка задачи |
| Взаимодействие с LTV | Правило только понижает approve → review; ветки review/reject по LTV не меняются (пробег не «спасает» от reject и не ужесточает review) | по умолчанию, консервативно |
| Пустой пробег | Без изменений: ValidationException «Пробег от 0 до 500000» | существующее поведение |
| Где порог | Новый ключ `vehicle.mileage_review_max_km = 400000` в `backend/config/rules.php`; `max_mileage_km = 500000` не трогаем | по плану |
| Причина решения | В ответ API поле причины не добавляем — решение без объяснений | по плану |

## Открытые допущения (требуют подтверждения риск-менеджмента)

Заказчик не подтвердил ни одно из решений выше («не знаю / решай сам»).
Все пять пунктов приняты по умолчанию из формулировки задачи и существующего
плана. Перед финализацией спеки подтвердить у риск-менеджмента:

1. Включительность границы 400 000.
2. Не ужесточает ли высокий пробег review → reject.
3. Поведение при отсутствии пробега (сейчас — отказ на валидации).
4. Не нужен ли код причины понижения в ответе API.

## Вне scope

- Фронтенд, БД, репозиторий.
- `ltv_by_age` (LOAN-12).
- Сравнение пробега «одометр против слов клиента» (CASE-08 / client_note).
- Валидационный предел `max_mileage_km = 500000`.
- Поле причины решения в ответе.

## Критерий готовности

При LTV в зелёной зоне: mileage 400 000 → approve; 400 001 → review
с `approved_limit = 0`. Ветки review/reject по LTV не меняются.
